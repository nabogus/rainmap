# RainMap

แผนที่ฝนประเทศไทย 2 หน้า

- **ฝนตอนนี้**: เรดาร์ย้อนหลัง 2 ชม. และคาดการณ์ (nowcast) ล่วงหน้า 2 ชม. เลือกได้ 2 แหล่ง
  - ทั้งภูมิภาค: เรดาร์รวมจาก RainViewer ทุก 10 นาที โหลดตรงจาก browser และคำนวณคาดการณ์เองใน `nowcast.js`
  - ไทย: เรดาร์กรมอุตุฯ และคาดการณ์ จากระบบสมดุลน้ำ กรมชลประทาน ทุก 15 นาที
- ชั้นข้อมูลเสริม เปิดปิดด้วยปุ่มในแผงควบคุม: **เมฆ** (ดาวเทียม Himawari ผ่าน NASA GIBS หน้าฝนตอนนี้) **ลม** และ **ความกดอากาศ** (GFS หน้าพยากรณ์ ค่า ณ ต้นวันของแต่ละวัน) และ **อุณหภูมิ** ต่ำสุดช่วงเช้ามืด / สูงสุดช่วงบ่าย รายวันตามปฏิทินไทย ปุ่ม 1/3/7/15 วันแสดงค่าสุดขีดที่จะเจอในช่วงนั้น (สลับกับชั้นฝนสะสม เพราะเป็นสีเต็มแผนที่ทั้งคู่)
- **มือถือ** (จอกว้างน้อยกว่า 768 px): แผนที่เต็มพื้นที่ แผงควบคุมลอยโปร่งใสที่ขอบล่างของแผนที่ คำอธิบายสีอยู่มุมซ้ายบน แหล่งที่มาเหลือแค่แถวล่างสุด บนคอมพิวเตอร์คงแบบเดิม แนวนอนบนมือถือ: ล็อกแนวตั้งด้วย `screen.orientation.lock` และ `manifest.json` เมื่อเบราว์เซอร์ยอม (เช่น Android ที่เพิ่มลงหน้าโฮม) iPhone ไม่ยอมให้เว็บล็อก จึงขึ้นหน้าให้หมุนกลับเป็นแนวตั้งแทน
- หน้า **อากาศตอนนี้** (เดิมชื่อฝนตอนนี้) มีชั้น **อุณหภูมิรายชั่วโมง** จาก GFS เลื่อนตามแถบเวลา ใช้ชั่วโมงที่ใกล้ที่สุด อยู่ใต้เมฆและฝน
- ปุ่มตำแหน่งปัจจุบัน: แสดงฝนตอนนี้ เวลาที่คาดว่าฝนถึง หรือฝนสะสมตามหน้าที่เปิดอยู่
- **ฝนคาดการณ์ 15 วัน**: ฝนสะสม 1 / 3 / 7 / 15 วัน จาก NOAA GFS ทั้งภูมิภาค (ลองจิจูด 90 ถึง 115 ละติจูด -5 ถึง 28) เลื่อนวันเริ่มได้

เรดาร์ดึงจากระบบสมดุลน้ำ กรมชลประทาน (ทดลอง) ซึ่งประมวลผลจากเรดาร์กรมอุตุนิยมวิทยา ส่วนฝนคาดการณ์ดึง GFS จาก NOAA NOMADS เอง
ถ้า NOAA ล่มและยังไม่มีไฟล์เดิม จะใช้ไฟล์ forecast ของกรมชลฯ แทน (เห็นเฉพาะประเทศไทย)
ไม่ใช่ประกาศเตือนภัย

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `fetch.py` | ดึงเรดาร์ (PNG 17 เฟรม) และเรียก forecast มาไว้ใน `data/` ใช้ Python มาตรฐาน ไม่ต้องติดตั้งอะไร |
| `fetch_gfs.py` | ดึง GFS APCP 15 ไฟล์ (f024 ถึง f360) ผ่าน grib filter ของ NOMADS แล้วคิดฝนรายวันจากผลต่างค่าสะสม ข้ามถ้ารอบเดิม |
| `grib2.py` | ตัวถอด GRIB2 แบบเล็ก (simple packing) เขียนเองเพราะเครื่องนี้บล็อก DLL ของ eccodes |
| `index.html` `app.js` `style.css` | หน้าเว็บ Leaflet อ่านไฟล์ใน `data/` |
| `layers.js` | ชั้นเมฆ (แปลง tile อินฟราเรดเป็นเมฆขาวโปร่งแสง) ลมเคลื่อนไหวบน canvas และเส้นความกดอากาศเท่าทุก 1 hPa พร้อมจุด H/L |
| `basemap.js` `basemap.json` | แผนที่ฐานของเราเอง (ค่าเริ่มต้น "แผนที่อากาศ"): พื้นบก/ทะเลโทนเข้มอยู่ชั้นล่าง เส้นชายฝั่ง เส้นแบ่งประเทศ/จังหวัด และชื่อภาษาไทยอยู่ชั้นบนสุด ทะลุเมฆและฝน |
| `tools/build_basemap.py` | สร้าง `basemap.json` จาก Natural Earth (สาธารณสมบัติ) รันเฉพาะเมื่อต้องการสร้างใหม่ ชื่อไทยของประเทศและเมืองกำหนดในไฟล์นี้ |
| `nowcast.js` | โหลด tile RainViewer (ซูม 4, 6 แผ่นต่อเฟรม) ถอดสีเป็น dBZ หาเวกเตอร์การเคลื่อนที่ด้วย block matching แล้วเลื่อนภาพล่าสุดไปข้างหน้า 12 ขั้น ขั้นละ 10 นาที |
| `.github/workflows/pages.yml` | GitHub Actions ดึงข้อมูลทุก 15 นาที แล้ว deploy ขึ้น GitHub Pages (ไม่ commit ข้อมูลลง repo) |

## รันในเครื่อง

```bash
python fetch.py
python -m http.server 8791 --bind 127.0.0.1
```

แล้วเปิด http://127.0.0.1:8791/

## ขึ้น GitHub Pages

1. สร้าง repo ชื่อ `rainmap` แล้ว push โค้ดขึ้น branch `main`
2. Settings > Pages > Build and deployment > Source เลือก **GitHub Actions**
3. รัน workflow ครั้งแรกจากแท็บ Actions (หรือรอ push) จะได้ที่ `https://<user>.github.io/rainmap/`

Workflow ตั้ง cron ทุก 15 นาที GitHub อาจหน่วงได้ 5 ถึง 15 นาที และจะหยุด cron เองถ้า repo ไม่มี commit นาน 60 วัน
(เข้าไปกด Enable อีกครั้งในแท็บ Actions)

## รูปแบบข้อมูล

- เรดาร์: PNG เทา 1301 x 1911 px โปรเจกชัน Web Mercator ค่าพิกเซล 1..6 = ระดับฝน ตาม `levels` (มม./ชม.) ใน `index.json`
- forecast: `daily.bin` uint16 little-endian ขนาด 15 วัน x 133 แถว x 101 คอลัมน์ ค่า x 0.1 = มม./วัน แถว 0 = ละติจูด -5 องศา (ใต้) คอลัมน์ 0 = ลองจิจูด 90 องศา ความละเอียด 0.25 องศา nodata = 65535 ขนาดกริดอ่านจาก `meta.json` เสมอ (ไฟล์สำรองของกรมชลฯ เป็น 65 x 37)
- วันของ forecast เริ่มที่ชั่วโมงของรอบ GFS (เช่นรอบ 00Z = 07:00 น. ไทย) ไม่ใช่เที่ยงคืน
- OPeNDAP ของ NOMADS ถูกยกเลิกแล้ว ต้องใช้ grib filter เท่านั้น
- เรดาร์ภูมิภาค: RainViewer แบบฟรีให้เฉพาะชุดสี Universal Blue ย้อนหลัง 2 ชม. ไม่มี nowcast และจำกัด 500 คำขอต่อนาที ภาพที่ใช้ละเอียดประมาณ 4.9 กม. ต่อพิกเซล แปลง dBZ เป็น มม./ชม. ด้วย Z = 200 R^1.6
- nowcast ที่คำนวณเองถือว่ากลุ่มฝนเคลื่อนที่คงที่ ไม่ก่อตัวใหม่ ไม่สลายตัว ทดสอบย้อนหลัง 12 พ.ย. 2569 (ฝน 1 มม./ชม. ขึ้นไป): CSI 0.45 ที่ 30 นาที และ 0.36 ที่ 60 นาที เทียบกับภาพนิ่ง 0.41 และ 0.31
- ลม/ความกดอากาศ: `wind.bin` int8 [16 เวลา][u แล้ว v][67 แถว][51 คอลัมน์] ค่า x 0.5 = ม./วินาที และ `pres.bin` uint16 ค่า + 85000 = Pa กริด 0.5 องศา เวลา k = ต้นวันที่ k (ชั่วโมงเดียวกับรอบ GFS) รายละเอียดอยู่ใน `meta.json` ช่อง `wx`
- เมฆ: GIBS เก็บภาพ Himawari ย้อนหลังประมาณ 4 ชม. ทุก 10 นาที และมาช้ากว่าเวลาจริงประมาณ 30 ถึง 40 นาที เวลาที่ไม่มีภาพจะตอบ 404 หน้าเว็บจึงถอยไปใช้ภาพล่าสุด (`default`)
- เมฆหลังเวลาภาพดาวเทียมล่าสุด (ช่วง 40 นาทีล่าสุดและคาดการณ์ 2 ชม.) เลื่อนตามสนามการเคลื่อนที่เดียวกับคาดการณ์ฝน (`NC.shiftAt` + `warpTile` ใน layers.js) แต่ละพื้นที่เลื่อนต่างกันได้ เมฆที่ไม่มีฝนอยู่ใกล้ใช้ความเร็วที่เกลี่ยจากบริเวณรอบ ๆ แหล่งไทยยืมสนามของทั้งภูมิภาคถ้าโหลดไว้แล้ว ไม่งั้นเมฆนิ่ง
- แผนที่ฐาน: Natural Earth 10m ไม่มีชื่อภาษาไทยของประเทศและเมือง (มีแต่จังหวัดไทยในช่อง `name_local` และผิดอยู่ 6 จังหวัด แก้ทับใน `PROVINCE_FIX`) เส้นเขตแดนเป็นแนวโดยประมาณ ไม่ใช่เส้นทางการ
- ลำดับชั้นบนแผนที่ (z-index): พื้นบก 150, tile/เมฆ 200, ฝน 400, ลม 450, เส้นเขตแดน 460, ชื่อ 470, หมุดตำแหน่ง 600
- อุณหภูมิ: `temp.bin` uint8 [15 วัน][ต่ำสุด แล้ว สูงสุด][133 แถว][101 คอลัมน์] ค่า / 2 - 40 = °C, 255 = ไม่มีข้อมูล ต่ำสุดใช้ TMIN ช่วง 6 ชม. ที่จบ 00Z (01:00-07:00 น.) สูงสุดใช้ TMAX ช่วงที่จบ 12Z (13:00-19:00 น.) ช่วงที่ผ่านไปแล้ว ณ เวลา init (เช่นค่าต่ำสุดของวันนี้เมื่อรอบ 06Z) จะไม่มีข้อมูล หน้าเว็บโหลดไฟล์นี้เมื่อเปิดชั้นอุณหภูมิเท่านั้น
- รอบดึง GFS ใช้ 31 ถึง 46 ไฟล์ (ฝน/ลมทุก 24 ชม. + ชั่วโมงของอุณหภูมิ) ประมาณ 1.5 นาทีต่อรอบใหม่
- อุณหภูมิรายชั่วโมง: `tnow.bin` uint8 [31 ชั่วโมง f000-f030][133][101] ถอดค่าเหมือน `temp.bin` ใช้ TMP ที่ 2 ม. เท่านั้น (ถ้าขอ var_TMP พร้อม lev_surface จะได้อุณหภูมิผิวพื้นติดมาด้วย ต้องเลือกด้วย level_type 103 ระดับ 2 ม.)
- เมื่อเปิดชั้นอุณหภูมิ ป้ายชื่อเมืองและจังหวัดแสดงตัวเลขอุณหภูมิของชั้นนั้นด้วย (ค่าที่จุดกริดใกล้ที่สุด)
- ไฟล์ js/css ใน index.html มี `?v=dev` ซึ่ง workflow เปลี่ยนเป็นรหัส commit ตอน deploy ให้ browser โหลดชุดใหม่พร้อมกัน (ถ้าโหลดคนละรุ่นจะเกิด error)
